## 1. TL;DR

- A **local-only** control panel for the HRSystem installation (Regina.HR: PWA + Node server + MySQL) on the Windows PC where it is installed. (The online access of v2.2.0 was removed in v2.3.0 at the owner's order; section 11.)
- Shows health/speed/backups/versions/logs/errors; can update, back up, restore, roll back, stop/start the app, send phone notifications.
- Two source files do almost everything: `server.mjs` (Node, no dependencies, ~3450 lines) and `public/index.html` (vanilla JS + CSS, ~3400 lines, no build step, no external request).
- Runs elevated, bound to `127.0.0.1`, protected by a per-run key (+ optional password).
- Updates itself every 10 min from the public GitHub repo `rogest-network/HRSystem-Dashboard` with automatic rollback.
- UI languages: Albanian (source), English, Serbian.

### Hard rules (never break)
1. **Local only.** It listens on and answers 127.0.0.1 / localhost only, and is never reachable from the internet (no tunnel route, no online sign-in: the online access of v2.2.0 was removed in v2.3.0, owner 2026-11-12: "heke mundësinë e lidhjes online të dashboardit, boje veç kështu local"). Never add anything that watches, probes or changes the live site, another site, Cloudflare zone settings, or a database other than its installation's. Probing the installation's *own* public address for the address-down alert is the only outward check.
2. **Never use drive D:** (the owner's external HDD). Everything lives on C:.
3. Never type/ask for the owner's passwords. Never print tokens/secrets (they are masked).
4. Dashboard-only changes publish **only** to the Dashboard repo (no asking). Program (`Source/`) changes are a different workflow (ask which repos). Installer scripts (setup, update, uninstall, SQL import) live ONLY in `Setup/Claude Studio/installer/` and the Setup zip; no repo carries them (owner, 2026-10-22: each repo holds only its own system).
5. Reply to the owner in **Albanian, short**; the closing list ("Lista jote") contains only things that need his action now.
6. Stay dependency-free (Node built-ins only) and `127.0.0.1`-only (any other `Host` header = 403).

## 3. Runtime model and security

- Started by Windows (scheduled task / `Dashboard.bat`), **elevated**, listens **only on 127.0.0.1**. A request with any other `Host` header gets 403 (also one that comes through a tunnel with another address). At start an `online-auth.json` left by v2.2.0 is deleted.
- On each start a random `SESSION_KEY` is generated and embedded in the served HTML. Every `POST /api/*` needs header `X-Manager-Key: <SESSION_KEY>` (403 otherwise; the page reloads itself once after a dashboard restart to pick up the new key).
- Plain GETs (status, errors, files lists) need no key. No path comes from the user for file operations: deletes/downloads/opens map a name against an internal list (path traversal returns 404).
- Optional password (`dashboard.key`): login page + session cookie valid while the browser stays open; 5 wrong tries lock for a minute; change requires the current one; "Hiq fjalëkalimin" removes it. `DASHBOARD_KEY` env var also works (cannot be changed from the UI).
- Request bodies are capped (small JSON 2–4 KB; SQL 50 MB; import 300 MB).
- Thrown errors in the router become `400 {error}` and are logged with `logError`.
- **`index.html` is read once at start. After editing the page, restart the server** (a stale page is the #1 false "my change doesn't work").

## 5. Frontend map (`public/index.html`), as of v2.4.0 (= the page of v2.0.6)

- Single page. Menu: Pasqyra (home), Të dhënat (data), Veprime (actions), Backup-et, Vendndodhja (files), Gabimet (errors, red count badge = errors in 24 h), Log-u, Historiku, Si ta përdorësh (help); Cilësimet (settings) in the footer/menu.
- Pages are functions: `pages.home | data | actions | backup | files | help | settings | errors | history | log`. `render()` rebuilds the current page from `state.data` (the status object); SSE `/api/live` and a poll refresh it. `load()` re-fetches status.
- Helpers: `el(tag, attrs, ...children)`, `sw(label, checked, onChange)` switch, `item(title, hint, control)`, `pill(kind, text)`, `call(name, query, okMsg)` (POST with key + toast, returns JSON or false), `postJson(name, body)`, `toast(msg, isError)`, `header(title, sub, actions)`, `fmtTime`.
- Persistence in the browser: `localStorage` keys `lang` (`sq|en|sr`, default `sq`), `section` (current page), theme and accessibility options.
- **i18n:** all UI source strings are Albanian. `TR_LIST` rows `[sq, en, sr]` build `TR_EXACT` (whole string) and `TR_FRAG` (fragments). `t(s)` = exact match, else whole-word fragment replacement (regexes with Unicode lookarounds, built once per language by `fragRegexes`) so a fragment never matches inside a longer word. **Every new visible string needs a TR_LIST row. Every message generated by the server (history titles, notification text, job output, error messages) needs one too**, otherwise English/Serbian show a mixed-language line. The Help page has three complete guides in `HELP` (sq/en/sr): update them when a feature changes.
- Accessibility (WCAG 2.2 AA) is a requirement: 44 px targets, strong focus rings, status symbols beside colours, no motion-only cues, pause for live updates, text spacing, forced-colors support. Don't regress it.
- Theme: CSS variables, light/dark/auto; must be usable at 375 px width.

## 6. Key flows (how things actually work)

- **Backup:** `/api/backup` → `mysqldump` (`--single-transaction`, utf8mb4) to `<data>/backups/<name>.sql` → `checkBackup` → history entry → optional off-PC copy. Auto backup runs at `autoBackupHour` (default 2), keeps `autoBackupKeep` (7). Failure → error notification + history.
- **Backup test:** creates temp DB, loads the dump, counts tables/users, drops the DB; result stored in `backupTests`, shown as "I provuar".
- **Update of the program:** `runUpdate` → `updater.ps1` (reads `update.json` {repo, channel}; `stable` = newest non-pre-release, `test` = newest incl. pre-releases) → backup, build, migrations, health check, automatic return on failure. Release asset name: `HRSystem-<x>.zip` (the only one accepted since dashboard 2.0.4; was: both accepted).
- **Self-heal:** app down >1 min and not manually stopped and autostart on → start it, notify.
- **Clear the app's cache (v2.5.0):** `POST /api/app-cache-clear?id=` → `appCacheClear(inst)` (`needLocal`; no job, it is instant): writes `<inst.root>\cache-epoch.txt` = one integer, `max(Date.now(), old + 1)`, plain ASCII digits, through `cache-epoch.txt.<pid>.tmp` in the same folder + `renameSync` (up to 10 tries 100 ms apart on EPERM/EBUSY/EACCES, the app may be reading the old file); a failure deletes the temp file, `logError('app-cache-clear')` and answers 400 "Cache-i i aplikacionit nuk u pastrua: skedari nuk u shkrua.". History "Cache-i i aplikacionit u pastrua" (detail "Pajisjet e marrin të freskët herën tjetër që hapin aplikacionin"); no phone message. CONTRACT with the program (from 1.0.19, built in `Source/` by the program side): the app reads that file, puts the number in its page, and its service worker drops every saved file and fetches fresh ones the next time a phone or browser opens the app; nobody is signed out. Older programs ignore the file. The status sends `appCacheAt` (`appCacheAt(inst)` reads the file; 0 = none). Page: item "Pastro cache-in e aplikacionit" in Veprime › Aplikacioni (button "Pastro cache-in", `confirmAsync`, toast, `load()`), a Ctrl+K action, the hint shows "Pastruar së fundi: <time>" and, when `installed.version` is below 1.0.19 by its first three numbers (1.0.18-b2, 1.0.17-test… count as older; 1.0.19-anything does not), "Vlen nga versioni 1.0.19 i programit.".
- **Address alert:** each learned public domain is requested every 30 s; 5 min down → alert, back → "Adresa u kthye".
- **Daily report:** composed from health, backup age/test, disk, addresses, version; level ok/warn/error by content.
- **phpMyAdmin (v2.0.5):** `POST /api/phpmyadmin?id=&lang=` → `pmaOpen`. Not installed (`tools\phpmyadmin-data\installed.json` + `tools\php\php.exe` + `tools\phpmyadmin\index.php`) → job "Instalimi i phpMyAdmin" (`pmaInstall`): phpmyadmin.net `home_page/version.json` gives the version and its `php_versions` ("<8.4" today → PHP 8.3); `windows.php.net/downloads/releases/releases.json` (redirects to downloads.php.net/~windows) gives the newest `nts-vs1x-x64` zip of 8.4 or 8.3 with its sha256; phpMyAdmin `…-all-languages.zip` is checked against its `.sha256`; both through `downloadVerified` (a wrong hash = nothing unpacked), unpacked with `System32\tar.exe` (fallback `Expand-Archive`) to `.php-new` / `.phpmyadmin-new`, moved to `tools\php` / `tools\phpmyadmin` (its `setup\` folder deleted), `php.ini` written, `php -v` + `php -m` (mysqli, mbstring, session) checked: exit 0xC0000135 or a vcruntime message = "mungon Microsoft Visual C++ Redistributable 2015-2022 (x64)". It does NOT honour `HR_TOOLS_DRY` (it changes nothing outside `tools\`). Installed → `pmaStart` (port 3510, else 3511-3519; `php.exe -c tools\php\php.ini -S 127.0.0.1:<port> -t tools\phpmyadmin tools\phpmyadmin-data\hrs-router.php`, `spawn` with `windowsHide`, a CHILD: libuv's job object ends it even when the dashboard is killed hard), writes `config.inc.php` (auth_type signon, SignonSession `HRSSignon`, SignonURL/LogoutURL = `hrs-signon.php` on that port, host/port from `.env` (`localhost` → 127.0.0.1), `only_db` = DB_NAME, AllowArbitraryServer false, ShowChgPassword false so nobody changes the app's DB password from there, VersionCheck off, random 32-byte `blowfish_secret` kept in `secret.hex`), `hrs-config.php` (paths of `.env` and of the token file only), `hrs-signon.php` and the router; then a one-time token: `signon-token.json` = {sha256 of the token, exp = now + 60 s, lang}; the page gets `http://127.0.0.1:<port>/hrs-signon.php?t=<token>`. `hrs-signon.php` deletes the token file before it compares (one use; an old token dies when a new one is written), reads DB_* from `.env`, fills `PMA_single_signon_user/_password/_host/_port`, redirects to `index.php?route=/database/structure&db=<DB_NAME>&lang=sq|en|sr@latin`; without a token it shows "Hape nga dashboard-i" (200; also the SignonURL target), a bad/used/expired token = 403 "Lidhja nuk vlen më", `?bye=1` (LogoutURL) ends the signon session. The router (`hrs-router.php`, outside the web root) answers 403 to any Host other than `127.0.0.1:<port>` / `localhost:<port>` (DNS rebinding) and 404 to phpMyAdmin's internal folders (`libraries`, `vendor`, `templates`, `sql`, `doc`, `examples`, `setup`, …), `config.inc.php`, root-level `.json/.lock/.md/…`, dot-paths, `..` and segments ending in a dot or space; the path is cut at "?" by hand (`parse_url` would read `//libraries/x` as a host). Each line php -S prints (one per request) is activity: 30 min without one (`HR_PMA_IDLE_MS` for tests) → `pmaStop(…, 'idle')`. `POST /api/phpmyadmin-stop` → `pmaStop(…, 'manual')`. Stop deletes `server.json`, the token and the PHP session files (the signon session holds the DB password while open, like `.env`). `process.on('exit')` kills it; SIGINT/SIGTERM/SIGBREAK now exit through `process.exit(0)` so that runs; 3 s after a start a `server.json` left behind is checked (the pid's ExecutablePath must be this php.exe) and cleaned. History: "Instalimi i phpMyAdmin" (the job), "phpMyAdmin u hap", "phpMyAdmin u mbyll" (detail: why). Page: `pmaOpen()` in `view()` opens the window at the click (blank, "Po hapet phpMyAdmin..."), on `{installing:true}` polls `/api/job` and asks again when the job ended OK, then sets the window's address. Buttons: Veprime › Databaza (item "phpMyAdmin": open + "Mbylle phpMyAdmin" while it runs), the Databaza card of the Glass/Minimal home, Ctrl+K action. Vendndodhja lists `tools` once it exists.
- **PHP in order (v2.3.0).** "Installed" means it really works. (1) `pmaInfo().installed` needs the record AND the files (`pmaFilesOk`: `php\php.exe`, `php\ext\php_mysqli.dll`, `phpmyadmin\index.php`, `phpmyadmin\vendor\autoload.php`): a folder that lost a part is "not installed", so `pmaEnsure` installs it again. (2) Health: `pmaVerify(inst, {fix, force})` runs `pmaPhpReady` (= `pmaCheckPhp`: `php -v` + the modules) and keeps the answer in `pmaHealth` (6 h when good, 10 min when bad; one check at a time per installation); the status only reads it (`pmaStatus`: the first look is started from there when nothing is known, state `checking`), never waits for it. `phpmyadmin.health` = `{state: 'ok', php: '8.3.36'}` | `{state: 'bad', error}` | `checking` | `unknown`; the 2.3.0 page showed it under the phpMyAdmin item and on Kryesore; the 2.4.0 page (= 2.0.6) does not read it. (3) A missing Visual C++ runtime (exit 0xC0000135 or a vcruntime message; the error carries `vc: true`) is repaired inside `pmaPhpReady`: `vcRedistFetch` downloads `https://aka.ms/vs/17/release/vc_redist.x64.exe` to `tools\downloads` (size cap 200 MB), asks PowerShell `Get-AuthenticodeSignature` and goes on ONLY when the status is `Valid` and the signer's subject has `O=Microsoft Corporation` (otherwise the file is deleted and nothing runs); `vcRedistInstall` runs it `/install /quiet /norestart` (0, 1638, 3010 = fine; 3010 says "restart the computer"), writes the history line "Microsoft Visual C++ u instalua", then PHP is checked again. Not tried again within 6 hours when it did not help (`vcTried`), **never with `HR_TOOLS_DRY=1`** (tests: the plain message stays). (4) Any other reason PHP does not start (a damaged php.exe, a missing module) is repaired by installing again: by `pmaEnsure` (at most once in 6 hours, `pmaRepairAt`; history "phpMyAdmin u riparua"; `installing` is true while it runs) or, at a click, by the same job as the first install. `pmaOpen` checks the health first, so the owner gets the real reason instead of "phpMyAdmin nuk u nis". `runCode` no longer throws for a file Windows cannot start (code -1). (5) `pmaCloseData(inst)` (in `pmaInstall` right after the folder is made and in `pmaStart` before the session files and the token are written): when the dashboard is ELEVATED (`isElevated()`: `fltmc.exe` exits 0; asked once per run) it runs `icacls <tools\phpmyadmin-data> /inheritance:r /grant:r *S-1-5-18:(OI)(CI)F *S-1-5-32-544:(OI)(CI)F`, because the install folder inherits "Authenticated Users: Modify" from C:\ and that folder holds the session file with the database password while phpMyAdmin is open, `secret.hex` and the one-time token. A dashboard that is not elevated (a test copy) skips it (it would lock itself out); a failure is logged once and never blocks phpMyAdmin. The new installer makes the same folder closed by itself; the dashboard covers the installs made before it.

## 8. How to change something (checklist)

1. Edit with the **Edit tool** (or byte-safe writes). Files may contain CRLF and `\\` sequences; shell here-docs/Python text mode have corrupted backslashes and line endings before. After a Python rewrite check `git diff`-style that nothing else moved.
2. New UI text → TR_LIST row (en + sr) and, if it is in a guide, the three `HELP` texts. New server message → TR_LIST row.
3. Syntax checks: `node --check server.mjs`; extract the last `<script>…</script>` of `index.html` to a temp file and `node --check` it.
4. Run a **test dashboard**: in `manager/` run `MANAGER_PORT=3700 node server.mjs` (hidden/background), restart it after every edit. Open it in the Browser pane. Note: a test dashboard needs the real install root to show an instance, otherwise it says "no installation found".
5. UI QA: every page × `sq`/`en`/`sr` × light/dark × phone width (resize_window mobile) ; read the console (no errors) and the Gabimet page; in `en`/`sr` scan the page text for leftover Albanian words.
6. API QA for new routes: no key → 403, bad id → 404, malformed JSON → 400, oversized body → 413/400, never a stack trace to the client.

## 9. Gotchas learned the hard way

- Stale page after editing `index.html` (cached at start) → restart the server.
- Stopping "only node" does not stop the app: the launcher restarts it. Always use `systemAction`.
- Windows PowerShell 5.1 + non-ASCII text without BOM = mojibake. Keep BOMs; avoid `&&`, ternaries, `?.` in `.ps1`.
- WMI/CIM hidden-window process starts need correct syntax; the quick tunnel runs hidden (no console windows popping up).
- A comment placed before code on the same line swallows the code; duplicate object keys are silent.
- Fragment translation inside words caused "Application nuk përgjigjet" — fixed with word-boundary regexes; keep exact rows for generated sentences.
- Cookies ignore ports, so the dashboard can hand a session cookie to the app on another 127.0.0.1 port (used by "open developer").
- GitHub token for the installation is fine-grained, Contents read-only, one repo. The dashboard's own repo is public and needs no token.
